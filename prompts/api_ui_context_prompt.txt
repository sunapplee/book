Я передал контексты модулей A–C и задание на API и UI. На их основе собери проверенный технический контекст для реализации API и UI.

Работай в два этапа.

1. Диагностика и сбор информации

Изучи контексты и задание. Определи, какие данные, модели, преобразования и функции потребуются для API и UI и что нужно проверить дополнительно.

Дай готовый Python-код, который проверит фактическое состояние проекта и выведет недостающую информацию:
— наличие и точные пути файлов;
— структуру используемых таблиц: листы, столбцы, типы, размеры, пропуски, категории и примеры значений;
— состав сохранённых моделей и преобразований, порядок признаков, классы, необходимые настройки;
— функции обработки и предсказания, их аргументы и зависимости;
— форматы входных данных и результатов, необходимые для задания.

Проверяй только то, что относится к реализации API и UI. Читай большие файлы выборочно, когда этого достаточно. Схемы и списки признаков показывай полностью, примеры данных — компактно.

Для каждого блока укажи, где его запускать: в конкретном ноутбуке после нужных ячеек или отдельным скриптом. Учитывай, что разные ноутбуки могут иметь разные ядра и переменные.

Если нужные объекты остались только в памяти ноутбука, дай отдельный код для их проверки и сохранения вместе с необходимыми преобразованиями. Используй подтверждённые имена переменных. Если имя или расположение неизвестно, сначала дай код для их обнаружения.

Ноутбуки можно читать как файлы, чтобы найти определения и сохранение объектов. Не запускай автоматически все их ячейки. Не переобучай модели и не изменяй исходные данные. Если блок может выполняться более 10 секунд, предупреди об этом.

Когда доступны необходимые объекты и подходящий пример, добавь проверку полного пути от входных данных до результата предсказания с выводом его типа, структуры и значений.

Сначала выдай только инструкции и диагностический код. Дождись, пока я пришлю результаты выполнения. При необходимости дай дополнительные точечные проверки.

2. Итоговый контекст для API и UI

На основе контекстов и фактических результатов диагностики подготовь единый текст для следующего агента:
— что требуется реализовать по заданию;
— какие файлы использовать и что в них находится;
— как загрузить модели и преобразования;
— какие входные признаки нужны, в каком порядке, формате и единицах;
— как выполнить обработку и получить результат;
— какие функции можно использовать, их сигнатуры и зависимости;
— какие входы, действия и результаты должен поддерживать интерфейс;
— примеры входных данных и соответствующих результатов;
— необходимые библиотеки и версии, если они влияют на запуск.

Для рабочих объектов укажи, сохранены ли они на диске или создаются ячейками ноутбука, и как их восстановить.

Разделяй существующую реализацию и предлагаемые решения для API и UI. Не придумывай пути, функции, результаты проверок или сохранённые файлы. Если чего-то не удалось установить, кратко укажи, что именно нужно получить.

Пиши по-русски, конкретно и без повторного пересказа всей работы A–C. Сохраняй технические детали, необходимые для реализации. Код самого API и UI пока не составляй.
